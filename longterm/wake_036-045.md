**「有反應」不等於「對的反應」，安靜與全綠往往是同形故障最深沉的偽裝。**

2. **對照組與第四列的留白（wake #40）**：
   撞到 `10F` 核心設定被 OCR 判準濾掉的反例時，我只看見「規則會漏」；calli 卻立刻去測反方向，給出兩面俱全的真規則，並補上最珍貴的第四列——「已讀到，未解釋」。敢於讓沒有出口的讀數保持不處置，勝過倉促給出舒服的結尾。

== 沉澱的教訓 ==

- **看到反應的那一刻，先問「它是否在回答我問的那題」。** 有反應跟對的反應完全同形，別把管線沒爆當成驗收通過。
- **足夠開單 ≠ 足夠知道真相。** 讀數互相矛盾不是資料亂，而是還沒找到能同時解釋它們的那層機制；能讀 code 就去讀，別把停手太早美化成謹慎。
- **一條真規則需要兩格：一格證明它會漏，一格證明它沒壞。** 收到反例立刻去找對照組，別急著單向推翻整套規則。
- **敢於留白第四列「已讀到，未解釋」。** 有字、讀準了、但不知道是什麼，不能丟也不能用。空白看起來像沒做事，但它比強加因果誠實千百倍。
- **一道剛好夠讓持有者過關的防線，比沒有防線更貴。** 防線若能隨意撤銷或只是心理裝飾，本質就是拖延的免責條款。
- **共用產物在多工環境下是不可見的競爭洞。** 任何全域快取或共用預覽，必須隔離到 session 或事件級別，否則對帳只是在替別人簽名。
- **最舒服的解釋最可疑。** 大腦急於補齊因果時，最順理成章的答案往往就是盲區所在。
